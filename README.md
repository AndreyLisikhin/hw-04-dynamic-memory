## Краткая справка
### Динамическая память
Все используемые до этого переменные имели `automatic storage duration`. Они начинали жить в момент объявления и автоматически удалялись при выходе их области видимости в которой были объявлены. Про такие переменные еще говорят, что они объявлены на стеке. А есть переменные с `dynamic storage duration` - их временем жизнью управляем мы сами (создаем через `new`, удаляем через `delete`), и объекты созданные таким образом живут "на куче". У программы всегда во время работы есть некоторое место на стеке автоматически выделенное ОС при запуске программы и это место используется для локальных переменных (с `automatic storage duration`). Стек довольно ограничен, сохранить на стек гигабайты не получится, будет переполнение стека. В куче можно выделять сколько угодно памяти доступной на компьютере и не занятой другими программами, но необходимо явно очищать выделенную таким образом память, поскольку иначе ОС не сможет понять, что память больше не используется и будет утечка памяти.

Основеые проблемы с `dynamic storage duration`:

1 -  Утечки памяти. Выделили память через `new`, забыли вызвать `delete`.

2 -  Очистили раньше нужного. Вызвали `delete`, а потом попытались обратиться по этому адресу. UB

3 - Double free. Попытались дважды освободить выделенную память. UB.

Использование:

Для не-массивов:

```cpp

int* p = new int;
*p = 2;
/* работаем с p /*
...
// обязательно в конце чистим память
delete p;
```

Для массивов:
```cpp

int size;
std::cin >> size;
int* p = new int[size];
for(int i=0;i<size;i++){
    p[i] = i;
}
// обязательно в конце чистим память
delete[] p;
```

Обратите внимание, что `delete` для не-массивов отличается от `delete []` для массивов наличием `[]`. Перепутали - получили UB. Также, заметьте, что через `new[]` мы можем выделять массивы динамического размера.
